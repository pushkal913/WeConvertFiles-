Remove a Known Password from an Authorized PDF Copy

Current Password Required

If you know the current password and are permitted to remove protection, an unlocked working copy can make legitimate tasks easier. The Decrypt PDF tool requires the existing password and creates a separate file named unlocked.pdf. It first tries to open and save the PDF directly; if that fails, it may fall back to rendering every page as a high-resolution JPEG and rebuilding a new PDF — which preserves the appearance but removes searchable text, links, forms, and other interactive features.

Open Decrypt PDF

Quick answer. Select a protected PDF that you are authorized to unlock, enter its current open password, and create unlocked.pdf. Always compare the output with the source, because the fallback path may reconstruct pages from images.

Authorization comes first

PDF encryption is an access control chosen by the document owner or publisher. Remove it only when you own the file or have clear permission to create an unlocked copy. Authorization may come from being the document owner, receiving the owner's permission, following an approved organizational process, migrating records under an authorized retention program, or creating a permitted accessibility or compatibility copy.

Knowing or obtaining a password does not automatically grant permission to redistribute, modify, publish, or remove protection from a document. Applicable contracts, workplace policies, confidentiality obligations, copyright rules, and local laws still apply. This tool is not designed to crack or recover unknown passwords.

When removing a known PDF password is useful

Create an approved working copy

A team may need an unlocked copy for a permitted internal process while preserving the encrypted original as the authoritative record.

Improve application compatibility

Some indexing, archiving, accessibility, printing, or conversion systems cannot process protected PDFs even when an operator knows the password. An unlocked derivative may work with those systems.

Reduce repeated password prompts

For a document stored in an appropriately secured environment, an authorized user may remove file-level protection so the password is not entered repeatedly.

Migrate records

An organization may need to move documents from a legacy password scheme into managed storage with centralized access controls.

Prepare for another PDF operation

Merging, organizing, extracting, or rotating pages may require an unencrypted working copy. Remove protection first only when the subsequent modification is permitted.

What you need

The protected PDF

One PDF that opens with a password. Damaged files, unsupported encryption methods, or unusual structures may still fail even when the password is correct.

The current password

Enter the exact password required to open the PDF, including capitalization, spaces, and symbols. The tool cannot derive or recover it.

Enough browser memory

Direct decryption and especially image rendering can use substantial memory. Large scanned documents and long PDFs are more demanding than small text files.

A secure destination

The unlocked result no longer requires the original password. Store and share it according to the sensitivity of its contents.

How to remove the password from a PDF

  1. 1. Confirm ownership or permission. Verify that the document owner and applicable policy allow an unlocked copy. If the PDF belongs to an employer, client, publisher, or public agency, follow its stated process.
  2. 2. Keep the protected original. Do not discard or overwrite the encrypted source. It may be required for authenticity, audit, legal, or recovery purposes, and it preserves features a fallback conversion may remove.
  3. 3. Test the password in a normal PDF viewer. Open the source in a current reader and confirm the password works. This separates password errors from tool or compatibility problems.
  4. 4. Select the PDF and enter the password. Use the exact credential that opens the document. Check keyboard layout, capitalization, punctuation, and accidental leading or trailing spaces.
  5. 5. Create the unlocked copy. Start the operation. The tool first attempts direct loading and saving; if that fails, it attempts the page-rendering fallback. The result downloads as unlocked.pdf.
  6. 6. Compare the output with the source. Open the result without a password and check page count and order, orientation, dimensions, text sharpness, text selection and search, hyperlinks, forms and annotations, bookmarks and attachments, accessibility tags, digital-signature status, and file size. Keep the original protected PDF even when the unlocked copy appears correct.

The two decryption paths

MethodWhat it doesMain advantageMain trade-off
Direct load and saveOpens the encrypted PDF with the password and saves an unlocked documentCan retain normal PDF page structureSome encryption methods or files may not load successfully
Rendering fallbackRenders every page at 2× scale, encodes it as JPEG at 0.95 quality, and builds a new PDFCan reproduce visible pages when direct saving failsFlattens content and removes interactive or semantic features

The interface may not prominently announce which internal path produced the download. The most reliable clue is the output itself: if text is no longer selectable or searchable, the rendering fallback was probably used.

Direct decryption and save

The preferred path:

  1. 1. Read the source PDF into browser memory.
  2. 2. Load it using the supplied password with encryption checks enabled.
  3. 3. Save the resulting PDF without reapplying password protection.
  4. 4. Download the output as unlocked.pdf.

This path avoids intentionally rebuilding every page as an image, so ordinary selectable text, vector graphics, and page content are more likely to remain in their normal PDF form. However, loading and saving through a different PDF library can still affect signatures, forms, annotations, metadata, embedded files, scripts, bookmarks, or unsupported structures, so verify complex documents.

Image-rendering fallback

If direct loading fails, the tool attempts a compatibility path:

  1. 1. PDF.js opens the source with the supplied password.
  2. 2. Each page is rendered to a canvas at twice its normal scale.
  3. 3. The canvas is encoded as JPEG with a quality setting of 0.95.
  4. 4. A new PDF page is created using the original page's width, height, and orientation.
  5. 5. The JPEG is placed across that page.
  6. 6. All reconstructed pages are saved as unlocked.pdf.

This can produce a visually similar copy, but it is not equivalent to removing encryption while leaving every original object untouched.

What the rendering fallback can remove or change

  • Selectable and searchable text: text becomes part of a page image and cannot normally be selected, copied, or searched unless OCR is performed later.
  • Hyperlinks: clickable links are flattened into pixels and no longer behave as interactive link annotations.
  • Form fields: text boxes, checkboxes, buttons, and calculations become part of the rendered page image.
  • Accessibility structure: tags, headings, alternative text, and logical reading order are not preserved in a JPEG page image.
  • Vector artwork: lines, diagrams, and fonts become raster content; fine details may look different when zoomed or printed.
  • Digital signatures: the fallback creates a different PDF, so existing signatures and their validation data are not preserved as valid signatures.
  • Attachments and navigation: embedded files, bookmarks, scripts, layers, and comments are not reproduced merely by rendering each page.
  • File size: the result may be larger or smaller; image-heavy sources behave differently from compact text-and-vector PDFs.

How to tell whether the output was flattened

Open unlocked.pdf and try these checks:

  1. 1. Select a sentence with the text-selection tool.
  2. 2. Search for a word visible on the page.
  3. 3. Click a visible hyperlink.
  4. 4. Place the cursor inside a form field.
  5. 5. Zoom closely into small text or vector lines.
  6. 6. Inspect the document's bookmarks and attachments.

If the page behaves like one large image, the fallback was likely used.

Decrypting is not password recovery

Decryption with a known password

The correct credential is supplied to open the PDF, and an authorized unlocked copy is created. This is the only operation this tool performs.

Password recovery

A person attempts to discover a forgotten password through guesses, wordlists, prior credentials, or other methods. The tool does not do this.

Password bypass

A person attempts to avoid or defeat the document's access control without valid authorization. The tool does not do this.

Security after removing the password

  • Store the unlocked file in an approved encrypted device or managed repository.
  • Limit folder and sharing permissions.
  • Avoid placing it in a publicly synchronized location.
  • Remove temporary copies when policy permits.
  • Do not email it without appropriate protection.
  • Consider re-encrypting it with a new password after approved modifications.
  • Keep the original protected file separately.

Removing one security layer should be accompanied by an appropriate replacement control when the contents remain sensitive.

Privacy and data handling

The PDF contents and entered password are processed in browser memory and are not sent to WeConvertFiles for decryption. Required JavaScript libraries may be downloaded from third-party content-delivery networks when the tool opens, so the workflow should not be described as completely offline.

If a visitor consents to site analytics, separate usage information such as visits, clicks, device details, or conversion events may be collected. Those analytics do not receive the PDF contents or the password entered into the tool.

The local environment still matters. Browser extensions, malware, clipboard history, screen recording, shared devices, downloaded files, and cloud-synchronized folders can expose confidential information independently of the decryption operation.

Troubleshooting

Incorrect password or failed to decrypt PDF

Confirm the password in a normal PDF viewer. Check capitalization, symbols, keyboard layout, and accidental spaces. If the password opens the file elsewhere, the PDF may use unsupported encryption or contain a structure the libraries cannot process.

Text is no longer selectable

The rendering fallback probably created image-based pages. Keep the original and use the unlocked copy only when loss of searchable text is acceptable.

Links and forms do not work

Interactive features are lost when pages are reconstructed from images. Use a desktop PDF editor or another authorized decryption workflow when those features must remain live.

Small text looks softer

The fallback renders at 2× scale and encodes pages as JPEG at 0.95 quality. Rasterization and JPEG compression can affect fine text and lines.

The output is much larger

Full-page images can occupy more space than efficiently encoded text and vector content. The effect depends on page count, dimensions, and visual complexity.

Page orientation or size looks wrong

Compare portrait and landscape pages individually. The fallback attempts to reproduce each original page size and orientation, but unusual page boxes require careful inspection.

A digital signature is missing or invalid

Creating an unlocked copy changes the document. Use the protected signed original when signature verification matters.

The browser becomes unresponsive

Rendering every page at 2× scale consumes memory. Close other heavy tabs or process a smaller authorized document when possible.

Frequently asked questions

Can I remove a PDF password if I do not know it?

No. The current password is required. The tool does not crack, guess, recover, or bypass unknown passwords.

Can I unlock any password-protected PDF?

Only unlock a document you own or are authorized to modify. A correct password does not automatically grant permission to remove protection or redistribute the contents.

Will the unlocked PDF keep searchable text?

It may on the direct-save path. If the rendering fallback is used, each page becomes an image and the text is no longer inherently searchable or selectable.

Are links and form fields preserved?

They may survive direct loading and saving, but they are flattened and lost as interactive features in the image-rendering fallback.

Does the fallback reduce quality?

It renders pages at 2× scale and uses JPEG quality 0.95, but it still changes vector and text content into raster images. Fine details, zoom behavior, and printing can differ from the source.

Does the tool overwrite the protected original?

No. It creates a separate file named unlocked.pdf.

Is the password saved by WeConvertFiles?

The password is processed in browser memory and is not sent to WeConvertFiles for decryption.

Can an unlocked PDF be protected again?

Yes. After authorized changes, a separate encryption workflow can create a newly protected copy with an appropriate password.

Why is the unlocked file larger?

If the fallback was used, full-page JPEG images may require more storage than the source PDF's text, fonts, vectors, and compressed assets.

Will a digital signature remain valid?

Do not assume so. Decryption and re-saving modify the document, while the fallback creates a reconstructed PDF. Keep the original signed file for verification.
